# Журнал поездок Splitaway — проект изменения

Этот файл описывает подготовленную миграцию `trip_registry.sql`. Она **ещё не применена** к рабочей базе.

## Что будет видно в Supabase

- `support.trip_overview`: код и название поездки, статус `active` / `completed` / `deleted`, даты, число участников и расходов.
- `support.trip_list`: компактный список поездок с названием, статусом, датами, числом участников и расходов, общей суммой. Начинайте поиск здесь.
- `support.trip_members`, `support.trip_expenses`, `support.trip_groups`, `support.trip_treasury`: отдельные понятные списки связанных данных. Фильтруйте каждый по `trip_id` из `trip_list`.
- `support.trip_events`: последовательность событий. Для поездок, существовавших до включения журнала, первое событие — `baseline`; это не дата создания.
- `support.deleted_trips`: закрытая таблица удалённых поездок. Каждая строка содержит все основные данные поездки в поле `payload`. Ключи доступа и привязки устройств не копируются.

Количество по статусам:

```sql
select status, count(*) from support.trip_registry group by status order by status;
```

Список поездок:

```sql
select * from support.trip_list order by status_at desc;
```

Посмотреть детали удалённой поездки (только в панели администратора):

```sql
select payload from support.deleted_trips where trip_id = '<код поездки>' order by id desc limit 1;
```

В Supabase Table Editor представления нельзя превратить в интерактивную страницу поездки: нажатие на строку не открывает связанные таблицы автоматически. Для поиска выберите строку в `trip_list`, скопируйте `trip_id` и примените фильтр `trip_id` в `trip_expenses` или другой таблице. Настоящее открытие поездки одним нажатием требует отдельной защищённой панели поддержки.

Отметить завершённую поездку или снова активировать её:

```sql
select support.set_trip_completed('<код поездки>', true, 'Поездка завершена');
select support.set_trip_completed('<код поездки>', false, 'Поездка снова активна');
```

После проверки обращения поддержкой восстановить удалённую поездку:

```sql
select support.restore_trip('<код поездки>', 'Номер обращения и основание проверки');
```

Результат последней команды содержит **новые** ключ приглашения и ключ администратора. Передавать их нужно только подтверждённому владельцу через защищённый канал. Старые ссылки и ключи после восстановления не действуют. Если участник меняет телефон, может потребоваться отдельно освободить привязку его имени к устройству.

## Ограничения

- Старые удалённые поездки восстановить нельзя: их снимков нет.
- Статус `completed` задаётся вручную в Supabase; в текущем приложении нет действия «Завершить поездку».
- В архив входят участники, группы, расходы и общая касса. Локальные данные телефона, чеки, хранящиеся только на устройстве, и push-подписки не восстанавливаются.
- Перед применением миграции требуется отдельное подтверждение владельца, проверка на изолированной базе и тест создания, удаления и восстановления тестовой поездки.
