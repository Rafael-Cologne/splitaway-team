МИГРАЦИЯ 021 — защита записи на сервере (Splitaway)
==================================================

Что закрывает
1. recover_session больше не выдаёт ключ приглашения постороннему (раньше хватало номера поездки и имени).
2. Запись расхода или группы с чужим id больше не перезаписывает другую поездку.
3. История изменений trip_history: старая и новая версия каждой изменённой или удалённой записи
   (расходы, участники, группы, касса). Приложение её не читает; восстановление — SQL-запросом.
4. Личный ключ участника: выдаётся при закреплении имени (claim_member_device), на сервере хранится только хэш.
   Соадмин получает права по своему ключу, ключ администратора ему не нужен.
5. Правила записи:
   - админ — всё, как раньше;
   - участник с ключом — добавлять расходы, менять и удалять только свои, добавлять погашения своей группы;
   - старое приложение без ключа — добавлять расходы и погашения; удалять или переименовывать участников,
     менять группы, кассу и название поездки, а также менять чужие расходы через синхронизацию нельзя.
6. Переименование админом в приложении 1.0.25 сохраняет запись участника (привязку к телефону и ключ).

Совместимость (проверено на локальной копии базы)
- Приложение 1.0.24 на новом сервере работает: расходы, группы, переименование, вход по ссылке,
  погашение, удаление расхода админом, картинки, освобождение имени.
- Приложение 1.0.25 на старом сервере тоже работает (новые параметры откатываются автоматически).
- Ограничения для старых версий:
  - соадмин на старом приложении не сможет менять участников, группы и кассу, пока не обновится;
  - после переустановки старого приложения нужно снова открыть ссылку-приглашение (раньше это была дыра).

Порядок применения
1. Резервная копия: Supabase → Database → Backups (или pg_dump).
2. SQL Editor → выполнить 021_member_keys_and_write_guards.sql (одна транзакция).
3. Опубликовать приложение 1.0.25.
4. Когда все участники обновятся: включить обязательный ключ, сначала для одной поездки:
     update trips set require_member_key = true where id = '<ID>';
   затем для всех. После этого запись без ключа отклоняется.
5. Откат при проблемах: 021_rollback.sql (возвращает прежние функции; история и новые колонки остаются).

Проверка: test_021.sql (только на тестовой базе — создаёт поездки T1/T2).

Ещё не закрыто (следующий шаг)
- Таблицы trips, members, expenses, groups и treasury читаются всеми, у кого есть публичный ключ Supabase
  (правило select = true). Нужна загрузка через защищённую функцию по ключу приглашения и замена
  живого обновления (realtime). Политика конфиденциальности должна это учитывать.


МИГРАЦИЯ 022 — закрыть открытое чтение данных
=============================================
Сейчас таблицы trips, members, expenses, groups и treasury может прочитать любой, у кого есть
публичный ключ Supabase из APK. 022 делится на два шага.

022a_secure_reads_prepare.sql — применить вместе с 021, до или одновременно с выпуском 1.0.25.
  Только добавляет, старые версии продолжают работать:
  - load_trip_data(ключ приглашения): вся поездка одним запросом и только по правильному ключу;
  - trip_signals: маленькая строка «в поездке что-то изменилось», по ней живое обновление;
    в ней нет ни имён, ни сумм, только хэш ключа и счётчик.
  Приложение 1.0.25 уже загружает данные так. Если 022a ещё не применена, оно читает по-старому.

022b_close_public_reads.sql — применить ПОЗЖЕ, когда почти все участники обновятся до 1.0.25.
  Закрывает прямое чтение таблиц. После этого:
  - версии 1.0.24 и старше перестанут загружать поездки;
  - вход только по коду поездки без ссылки или QR больше не откроет поездку (нужна ссылка-приглашение);
  - политика конфиденциальности («доступ защищён токенами») станет правдой.
  Откат 022b описан в конце файла (вернуть правила чтения).

Проверено на локальной копии базы с закрытым чтением (022b):
  приложение 1.0.25 загружает, синхронизирует и обновляет всё через защищённую функцию;
  прямое чтение таблиц отклоняется (permission denied); неверный ключ приглашения не даёт данных.

Полный порядок выпуска
1. Резервная копия базы.
2. Выполнить 021, затем 022a.
3. Выпустить APK 1.0.25.
4. Через некоторое время, когда участники обновятся:
   - включить обязательный ключ: update trips set require_member_key = true;  (сначала для одной поездки)
   - выполнить 022b.

=== 023_change_trip_currency.sql (build 38+) ===
Admin can change the trip base currency; all amounts are converted in ONE server transaction.
Phones still working in the old currency cannot overwrite converted amounts (they reload).
Order: 021 -> 022a -> 023  (022b later, as before). Safe to run 023 again.
If 021 or 021_rollback is run AFTER 023, run 023 once more.
Until 023 is applied, build 38 works normally; only the currency change shows "sync failed" and changes nothing.
Test (local Postgres): 11/11 in each order: today's server+023, 021+022a+023, 023->021->023.
